# 향후 개선 계획

[메인 README](../README.md) · [검색 성능 개선](search-performance.md) · [구현 현황](implementation-status.md)

이번 프로젝트는 2주 범위였습니다. 실제 서비스로 간다면 아래 순서로 진행합니다. 각 항목에 지금 관측된 근거와 완료 기준을 붙였습니다.

| 순서 | 작업 | 지금의 근거 | 완료 기준 |
|---|---|---|---|
| 1 | **등록된 기업 정보로 바로 검색** — 사업자번호로 등록한 소재지·업종·관심 분야를 AI 없이 즉시 필터하고, AI 추천은 백그라운드에서 미리 계산해 채팅에서 읽기만 | 기업 프로필이 검색·자격 판정에 연결돼 있지 않음. 검색 42초 중 88%가 LLM 랭킹 | 채팅에서 "우리 회사에 맞는 공고" 응답 1초 내, 추천은 기업 등록·카탈로그 공개 시점에 사전 계산 |
| 2 | **랭킹·임베딩 캐시를 Redis로 공유** | 캐시가 프로세스 메모리(5분)에만 있어 재시작·다중 인스턴스에서 사라짐 | 같은 소재지·업종 기업이 계산 결과를 공유, 카탈로그 지문으로 무효화 |
| 3 | **자유 입력 이해와 자격 조항 추출** — 의도 라우터, 공고별 자격 조항 추출(공고당 1회 저장) + 규칙 판정, 서류 체크리스트 | 자격 판정이 요청마다 LLM 판단. 공고 형식이 정해진 질문에만 잘 답함 | 조항 추출 정확도를 사람 검수 표본으로 측정, 규칙 판정은 코드로 재현 |
| 4 | **K-Startup·과기정통부 실데이터 품질 비교 후 기본 활성화** | 연동 코드는 완료, 기본 OFF. 과기정통부는 접수 기간 미제공 | 제공처 간 중복·추가 공고·추천 품질을 독립 표본으로 비교한 보고서 |
| 5 | **원문 근거 범위 확대** — K-Startup 상세, 첨부 PDF/HWP 본문의 청크 색인 | 원문 질문은 기업마당 HTML만. 공고당 청크 1개 사례가 많음 | 다중 청크 검색 품질 평가, 첨부 파싱 실패율 기록 |
| 6 | **외부 공개 전 운영 검증** — 동시 부하·요청 제한·관측, Vercel + AWS 실제 배포, 이메일 실전달 | Compose는 개발용, 배포는 설정 준비만 | 부하 시나리오 통과, 배포 완료 기록, 백업·복구 절차 |
| 7 | **평가 자료에 사람 검증 정답 추가** | 모든 판정이 AI 작성. 전 구간 AI 검색 평가는 양성 질문 2개 | 사람 검수 100문항 이상, dev/heldout 분리 유지 |

## 모델 고도화로 풀 수 있는 것

- 자격 조항을 구조화해 두면 "우리 회사가 되는지"를 규칙으로 즉시 답할 수 있고, LLM은 애매한 조항 해석에만 씁니다.
- 스트리밍 응답을 붙이면 전체 시간은 같아도 첫 문장이 먼저 보여 체감이 좋아집니다.
- 리랭커(cross-encoder)를 넣으면 LLM에 넘기는 후보를 20 → 8로 줄여 랭킹 시간을 낮출 수 있습니다. 후보를 줄였을 때 놓치는 공고가 없는지 300문항으로 먼저 확인합니다.

## 실제 적용처

- 기업마당·K-Startup 사용자에게 "원문 근거로 자격 확인 + 서류 준비"를 붙이는 보조 도구.
- 지자체·창업지원기관 상담 창구의 사전 검토 도구(중복 수혜 검토 근거 이력 활용).
